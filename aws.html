講座の全体像

講座の目的と特徴

学習のゴール

サーバーサイドエンジニアとしてインフラに苦手意識があった講師が、その経験を元に、インフラ構築に抵抗のある人でもAWSでサーバーやネットワークを構築・運用できるようになることを目指します。

3つのポイント

1. ゼロからの構築: AWSの基礎知識を座学だけでなく、実際に手を動かしてサービスを構築しながら習得します。 2. 実用的なサービスと設計パターン: 利用頻度の高いAWSサービスを取り上げ、その使い方に加え、設計パターンも学びます。 3. インフラの基礎知識習得: 構築を通じてインフラの基礎を身につけ、個人サービスの構築や障害対応能力の向上を目指します。

講座の構成と対象者

学習カリキュラム

- 構成: - 基礎編: WordPressサービスの構築を通じて、AWSの主要サービス（VPC, EC2, Route 53, RDS）とネットワークの基礎（IP, TCP, UDP, SSH, ファイアウォール, DNS, HTTP）を学びます。 - 発展編: 構築したWordPressサービスの冗長化や画像配信機能を追加し、より運用に耐えうる構成を目指します。AWSサービス（ELB, S3, CloudFront, CloudWatch, IAM）と運用に関するインフラ知識（冗長化、キャッシュ、監視、アクセス権限）を習得します。

対象者

AWS初心者、インフラに詳しくない方、AWSを使ってネットワークサーバーを構築したいアプリケーションエンジニア。

基本用語解説
サーバーサイド

Webサイトの「裏側」で作動するシステム。データの保存や計算を担当します。

インフラ

ITの基盤。水道や電気のようにシステムが動くために必要な設備です。

冗長化

予備の機器を用意しておくこと。一つが壊れてもサービスが止まりません。

1. 初期設定：AWSを始めよう

初期設定の実施（実践）

アカウントと費用管理

アカウント作成

AWSアカウントの作成方法を習得します。

料金アラートの設定

想定外の費用発生を防ぐため、一定額を超えたらメールで通知するよう設定します。

セキュリティとログの確保

IAMユーザーの作成

セキュリティのベストプラクティスに基づき、日常業務にはルートユーザーではなくIAM（Identity and Access Management）ユーザーを使用します。管理者権限を持つIAMユーザーを作成し、請求情報へのアクセスを許可します。

操作ログの記録 (CloudTrail)

誰がいつAWSで何をしたかを記録するため、CloudTrailでS3バケットへのログ保存を設定し、90日間のデフォルト保存期間を延長します。

AWSサービス用語解説
IAM

AWSの「認証・認可」を司るサービス。誰がどのサービスを操作できるかを細かく設定します。

CloudTrail

AWSアカウント内の操作履歴をすべて記録するサービス。監視カメラの役割を果たします。

2. VPC：ネットワークを構築しよう

ネットワークの重要概念

システムの全体像とAWSネットワーク

構成イメージ

パブリックサブネットにWebサーバー、プライベートサブネットにデータベースサーバーを配置するWordPressシステムのネットワーク構成を理解します。

ネットワークの構成要素

- リージョン: AWSサービスが提供される地理的地域（例: 東京リージョン）。 - アベイラビリティゾーン (AZ): 独立したデータセンター群。複数のAZにリソースを配置することで耐障害性を高めます。 - VPC (Virtual Private Cloud): AWS上に論理的に隔離された仮想ネットワークを作成するサービス。 - サブネット: VPCをさらに分割したネットワーク空間。インターネットからアクセス可能なパブリックサブネットと、アクセスできないプライベートサブネットがあります。

IPアドレスと範囲指定

IPアドレスの基礎

ネットワーク上の機器を識別する「インターネット上の住所」。32ビットの整数値を8ビットずつに区切り、ドット区切りの10進数で表現します。インターネットに接続するために一意のパブリックIPと、内部ネットワークで使用されるプライベートIPがあります。

CIDR表記

IPアドレスの範囲を「10.0.0.0/16」のように表現し、ネットワーク部とホスト部を定義します。

ネットワーク構築（実践）

VPCとサブネットの作成

VPCの作成

東京リージョンに「10.0.0.0/16」のCIDRブロックを持つVPCを作成します。

サブネットの作成

VPC内にパブリックサブネット（10.0.1.0/24）とプライベートサブネット（10.0.2.0/24）をそれぞれ作成します。

ルーティングの設定

インターネットゲートウェイ (IGW) の作成

VPCとインターネットを接続する仮想ルーターを作成し、VPCにアタッチします。

ルートテーブルの作成と関連付け

パブリックサブネット用のルートテーブルを作成し、デフォルトルート（0.0.0.0/0）をIGWに設定してインターネット接続を可能にします。

AWSサービス用語解説
VPC (Virtual Private Cloud)

AWS上に構築できる自分専用の「仮想プライベートネットワーク」空間。

IGW (Internet Gateway)

VPC内のネットワークを外の世界（インターネット）と繋ぐための「出入り口」。

3. EC2：Webサーバーを構築しよう

EC2の基礎知識

仮想サーバー (EC2)

EC2と関連概念

- EC2 (Elastic Compute Cloud): AWSクラウド上の仮想サーバー。短時間で起動し、柔軟なスペック変更が可能です。 - AMI (Amazon Machine Image): OSイメージのテンプレート。 - インスタンスタイプ: EC2サーバーのスペック（CPU, メモリなど）を定義。 - ストレージ (EBSとインスタンスストア): 永続的なEBSと一時的なインスタンスストアの使い分け。

構築の実践ステップ

EC2：Webサーバーを構築

起動と接続設定

パブリックサブネットにAmazon Linux 2を起動し、SSH（公開鍵認証）でログイン。セキュリティグループでHTTP（ポート80）からのアクセスを許可し、IPアドレス変動を防ぐため固定IP（Elastic IP）を割り当てます。最後にApacheをインストールして起動設定を行います。

AWSサービス用語解説
EC2

使いたい時に数分で立ち上げられ、不要になれば消せる「仮想サーバー」。

AMI / インスタンス

AMIはサーバーの「金型」、インスタンスはその金型から作られた「実体」です。

4. Route 53：ドメインを登録しよう

ドメインとDNSの基礎知識

ドメインとDNS (Route 53)

インターネットの名前解決とRoute 53

Webサイトにアクセスする際の「awsandinfra.work」のようなドメイン名をIPアドレスに変換（名前解決）するシステム。Route 53はAWSが提供するDNSサービスで、ホストゾーン（DNSレコードの集合）などを管理し、高い可用性を持ちます。

構築の実践ステップ

Route 53：ドメインを登録

DNSのルーティング設定

レジストラでドメインを購入後、Route 53でホストゾーンを作成し、ネームサーバーを変更。ドメイン名とWebサーバーのElastic IPを紐付けるAレコードを登録します。

AWSサービス用語解説
Route 53

AWSのドメイン管理・DNSサービス。「落ちないDNS」として有名です。

Aレコード

ドメイン名（名前）とIPアドレス（住所）を1対1で紐付けるための設定情報です。

5. RDS：DBサーバーを構築しよう

データベースの基礎知識

マネージドデータベース (RDS)

RDSの特徴

フルマネージドなリレーショナルデータベースサービス。バックアップやアップデート等の運用管理をAWSが代行し、高い可用性（マルチAZ）を容易に実現します。

構築の実践ステップ

RDS：DBサーバーを構築

プライベートなDBの作成

プライベートサブネットにMySQL 8.0のRDSインスタンスを作成。パブリックアクセスは無効化し、セキュリティグループでWebサーバーからのアクセス（ポート3306）のみ許可します。

AWSサービス用語解説
RDS

DBの面倒な管理作業（バックアップや更新）を自動で行ってくれるサービス。

マルチAZ

複数のデータセンターにまたがって予備を持たせ、障害に強くする仕組みです。

6. WordPressを構築しよう

構築の実践ステップ

WordPressを構築

最終セットアップ

WebサーバーからMySQLに接続してDBとユーザーを作成。EC2にPHP等をインストールし、WordPressファイルを配置。ブラウザからセットアップ画面にアクセスし、インストールを完了させます。

🚀 発展編：運用と拡張

インフラの総まとめ・運用と拡張

インフラの総まとめ（TCP/IP）

WordPressサイトが表示される仕組み

通信の全体像

Webブラウザからのドメイン名によるアクセスから、Route 53による名前解決、EC2へのHTTPリクエスト、ApacheとWordPressの処理、RDSからのデータ取得、最終的なWebページの返送までの一連の流れ。

TCP/IPとHTTP

- TCP/IP 4階層モデル: アプリケーション層〜ネットワークインターフェース層の構造。 - HTTPプロトコル: ブラウザとサーバー間の「リクエスト」と「レスポンス」。 - TCP: パケットの順序制御や再送制御を行い、正確さを保証する信頼性重視の通信。 - UDP: 速度を重視する一方的な通信。 - IP: IPアドレスを用いてパケットを宛先に届ける役割。

AWSサービスによる運用と拡張

パフォーマンスと可用性の向上

画像配信の高速化 (S3 & CloudFront)

- S3: 安価で耐久性の高い、容量無制限のクラウドストレージ。Webサーバーから画像を分離することでストレージ枯渇防止やステートレス化を図ります。 - CloudFront (CDN): コンテンツを高速に配信するためのマネージドサービス。エッジサーバーにキャッシュし、画像表示の高速化とサーバー負荷軽減を図ります。

WebとDBの冗長化 (ELB / RDS Multi-AZ)

- Webレイヤーの冗長化 (ELB): 複数のサーバーにアクセスを自動分散し、負荷分散と高可用性を実現します。 - DBレイヤーの冗長化 (RDS Multi-AZ): RDSをマスター/スレーブ構成にし、障害発生時は自動的にスタンバイに切り替わります。

監視とセキュリティ

システム監視 (CloudWatch & Amazon SNS)

- CloudWatch: AWSサービスのリソース状況（メトリクス）を監視し、しきい値を超えるとアラームを発生させます。 - Amazon SNS: アラーム発生時にメール等で通知を行うサービス。

アクセス権限の管理 (IAM)

最小限の権限付与などのベストプラクティスを実施。EC2等のAWSリソースから別サービスを操作する際は、一時的なアクセス許可である「IAMロール」を使用します。

AWSサービス用語解説
S3 (Simple Storage Service)

容量無制限で安価にデータを保存できる「オブジェクトストレージ」。

CloudFront

世界中にあるサーバーにデータを一時保存し、ユーザーに近い場所から配信するCDN。

ELB (Elastic Load Balancing)

アクセスが集中した際に、背後にある複数のサーバーへ自動的に通信を振り分けるサービス。

CloudWatch

サーバーのCPU使用率などを監視し、異常があればアラームを鳴らす監視サービス。
